# Ekspor dan penyimpanan audit HOMEKU 3.1

Lanjutkan fase 4 di `audit/authoring.md`. Jika audit kerja berubah, buat kandidat terbaru dan jalankan `review`. Ekspor langsung dengan receipt yang dihasilkan.

~~~sh
python tools/audit.py review work/candidate/rumah --output work/review.md --session work/audit/session.json
python tools/audit.py export work/candidate/rumah --receipt work/review.md.json --output work/final --session work/audit/session.json
~~~

## Fase 5 — Simpan hasil di Google Drive

Langsung mulai `drive-delivery` di chat dan workspace yang sama. Gunakan `delivery-plan` dengan `package` dan `package_sha256` dari ekspor terakhir serta nama asli MP4 di Drive. Jalankan langkah berikut sebelum menyatakan hasil tersimpan.

1. Temukan satu folder `Audit` yang merupakan anak langsung dari root `HOMEKU` yang diberikan pengguna. Cari folder dengan nama persis `drive_path[1]` di bawah `Audit`. Saat mencari folder atau file, batasi ke induk yang benar, kecualikan item di sampah, dan periksa semua halaman. Jika nama ganda, tipe item salah, atau induk tidak dapat dipastikan, laporkan konflik sebelum mengubah isi.
2. Buat folder video jika belum ada. Untuk folder yang sudah berisi hasil, unduh ZIP dengan revisi tertinggi dengan nama kanonisnya, lalu ulangi `delivery-plan` dengan `--previous /path/<id>-rNNNN.zip`. Cocokkan ID audit dan SHA-256 MP4 yang terikat pada manifest, termasuk ketika dua video memiliki nama dasar yang sama. Jika ada ZIP ambigu, sumber berbeda, atau revisi Drive lebih baru, hentikan dan laporkan konflik. Sebelum menulis, catat ID folder Drive, nama video, SHA-256 sumber, dan SHA-256 paket ekspor di `drive-progress.json` di samping `plan.json`, serta ID, SHA-256, dan jalur unduhan lokal ZIP Drive sebelumnya jika ada. Folder yang belum punya ZIP dan sudah berisi file hanya boleh dilanjutkan dengan checkpoint dari sesi yang sama yang cocok dengan folder, sumber, dan paket ini.
3. Gunakan hanya daftar `files` dari rencana. Simpan `analysis.md` sebagai file Markdown mentah dan JPEG dalam satu subfolder `media`. Buat `media` jika belum ada. Inventarisasi nama yang dituju sebelum menulis. Untuk setiap file, cek tipe dan SHA-256 file Drive. Pakai ulang file bila hash sama, perbarui byte dengan ID Drive yang sama bila berbeda, dan buat file bila belum ada. `comparison` membandingkan dua ZIP dan membantu memilih file untuk diperiksa, tetapi cek file aktual di Drive sebelum melewatinya. Gunakan checksum SHA-256 dari Drive atau hitung dari byte mentah. Verifikasi ulang berkas yang ditulis. Laporkan nama media lama yang tercantum di `obsolete_media` dan masih ada di Drive. Biarkan file lama tersedia. MP4 asli tetap di `HOMEKU/Video`.
4. Setelah laporan dan semua JPEG selesai diverifikasi, unggah atau perbarui `<id>-rNNNN.zip` terakhir. Jika nama kanonis berubah karena revisi baru, buat file ZIP dengan nama baru. Unduh byte ZIP yang tersimpan dari ID Drive hasil transfer dan cocokkan SHA-256 dengan `package_sha256`. Tandai fase `finish` hanya setelah semua file yang direncanakan terverifikasi. Jalankan `performance`.

Jika transfer terputus, sebutkan operasi dan nama file yang tertunda serta status fase. Sediakan unduhan ZIP di chat. Untuk melanjutkan, pakai ekspor dan checkpoint yang sama, verifikasi kembali folder dan ZIP yang ada, dan lanjutkan file yang belum cocok. Jika ZIP Drive berubah di luar hasil ekspor ini atau ZIP sebelumnya yang tercatat, laporkan konflik sebelum menimpa. Jika ZIP Drive sudah cocok dengan ekspor ini, gunakan salinan lokal ZIP sebelumnya dari checkpoint untuk tetap melaporkan media lama yang keluar dari inventaris. Tawari penyimpanan manual jika kemampuan Drive tidak tersedia. Jika audit dimulai tanpa tujuan Drive, sampaikan bahwa ekspor lokal selesai dan fase Drive menunggu tujuan.

Dalam satu balasan akhir, tampilkan ringkasan shot, laporan, Overview, Storyboard, kolase, tautan unduhan ZIP, dan status fase 5. Setelah transfer terverifikasi, sertakan tautan folder dan ZIP Drive. Ambil tautan laporan dan media lokal dari checklist `review` dan jalur ZIP dari `export`. Ingest tetap dijalankan setelah pengguna secara eksplisit memilih ZIP untuk dijadikan referensi, dengan MP4 kanonis terpisah.
